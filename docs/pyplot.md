# PyPlot Overview

PyPlot provides the common desktop workbench: file import, worksheet management, graph tooling, Origin export, and project save/restore all live here so plug-ins only need to supply their domain-specific panels and load/generate logic. This page tracks those shared capabilities and points to the plug-ins that build on them.

## Workbench Basics

- **Project Explorer** lists imported workbooks, worksheets, and generated graphs. Every plug-in uses the same tree so you can keep one set of worksheets available while switching tools.
  Empty-state behavior: `Imported Data` now appears only after at least one workbook/sheet is actually imported.
  Worksheet activation: double-click opens worksheet entries by worksheet key (not only path-backed sheets), and worksheet-group entries now open their first worksheet when possible.
  Stability: stale/deleted Project Explorer items are ignored during tab focus sync and workbook cleanup, preventing post-close selection/focus errors.
  Readability note: long names/paths now use middle elision, improved column sizing, alternating rows, and tooltips with full text so dense imports remain navigable.
  Search note: the dock now includes a search box that filters tree items by name/details/path text while keeping matching parent branches visible.
- **Object Manager** mirrors the current Matplotlib tab (axes, lines, legends, annotations) and lets you tweak selections via the toolbar actions.
- **Legend sync** now follows line visibility toggles and graph-format applies: legends are rebuilt from currently visible lines so hidden series are not listed.
- **Toolbars** (Plugin, Plot actions, Navigation, Format) live at the top. Enabled actions now show a subtle highlight so you can immediately see what is clickable; disabled items stay muted.
  Navigation continuity: when `Zoom` or `Pan` is active, switching between graph tabs now keeps that navigation mode bound to the newly active canvas instead of resetting the mode.
- **Shared task progress** appears in the status bar for long operations (for example import, plotting, and Origin export flows) whenever the host/plugin uses the shared progress helpers (`_begin_task_progress`, `_update_task_progress`, `_end_task_progress`). The progress widgets now sit to the right of the `x/y` cursor readout and are preferred over per-task modal progress dialogs in shared plotting/import flows.
  Cursor readout clipping: the status-bar `x/y` label now uses compact/elided formatting when horizontal space is tight so values remain visible even with narrow dock layouts.
  Responsive status layout: when progress widgets are visible, status-bar widths now rebalance dynamically so the cursor readout keeps a readable minimum width instead of being pushed out on narrow windows.
- **Graph formatting** is shared across plugins: PyPlot exposes a single shared `Graph formatting` section (de-duplicated across plugin menus) for title/X/Y labels (with per-label show/hide checkboxes), font sizes, tick size/width, tick mode (`Auto`, by increment, or by target count), figure width/height, axes aspect mode (`Auto`/`Equal`/custom ratio), line+marker size, linear/log axis scale, explicit axis limits, grid, and legend controls, then apply to the current graph or all open graphs.
  Graph-format layout: the Graph formatting window is now tabbed (`Text`, `Axes`, `Ticks`, `Legend`) so legend location/orientation/font/columns/symbol/follow-colour/draggable options are managed in the same shared place instead of per-plugin dialogs.
  Axis value formulas: each axis now supports a display factor expression (for example `10^-3`) with optional unit-label reflection.
  Access note: use the top-toolbar `Graph formatting` section button to open the dedicated movable Graph formatting dialog (not a clipped popover).
- **Axis unit style** defaults to square brackets in shared graphs (for example `Temperature [°C]`, `Strain [%]`).
- **Large-font safety**: graph-format applies run a layout fit pass so oversized title/label/tick fonts are kept inside the canvas bounds.
- **Direct on-canvas editing** is available on Matplotlib graphs: double-click title/X/Y label text, legend entries/box, or near an axis line to open the shared movable Graph formatting dialog, focused on the relevant controls (labels, legend, or axis scale/limits). If shared controls are unavailable for a host/plugin, PyPlot falls back to the legacy direct-edit dialogs.
  Curve formatting shortcut: double-clicking a plotted line/marker now opens the shared Graph formatting window focused on line/marker controls, matching the direct-object editing flow users expect from desktop plotting tools.
  Canvas shortcuts/menu: when a graph canvas is focused, `Cmd/Ctrl+C` copies the graph as PNG to the clipboard. Right-clicking a graph canvas opens a quick menu with `Copy graph as PNG` and `Export graph...`.
  Object Manager parity: double-clicking a legend item in Object Manager now opens the same shared Graph formatting legend controls before falling back to legacy dialogs. Right-clicking a legend item now also exposes `Reconstruct legend`, which rebuilds the legend from the currently visible plotted lines.
- **Dock switchers** sit on the left/right edges so you can collapse/restore the Project Explorer, Message Log, and Object Manager without losing their placement (enabled across platforms). Switchers now use click-to-toggle behavior (no hover pop-out/auto-collapse) to avoid resize flicker.
- **Settings → Graph options** provides shared defaults for all plugins plus optional per-plugin overrides (for example grid/legend defaults, font sizes, line width/marker size, default figure width/height, legend defaults) so plugin-specific behavior can diverge without duplicating UI code. The dialog now uses `Apply`, `Cancel`, and `Reset to defaults`; `Apply` immediately refreshes all open graphs.
  Layout warning feedback: if Matplotlib reports `Tight layout not applied`, PyPlot surfaces a warning with likely oversized text objects, measured font sizes, and suggested size targets, then lets you keep current sizes, auto-fit only the current graph, or apply plugin graph-option overrides from the recommendation. The warning now also supports applying your selected action to all affected graphs in the current batch.
  Override persistence rule: the layout-warning `Apply plugin override` path now stores only the recommended plugin-specific font fields instead of copying the full effective graph geometry into a plugin override.
  Saved-override prompting: existing plugin overrides no longer auto-reapply silently when a new tight-layout warning appears; PyPlot keeps prompting so saved overrides cannot appear to turn themselves on.
- **Responsive side docks**: Project Explorer/Object Manager now reopen at the last remembered session width, keep user-shrunk widths when the session closes, and avoid visibility-triggered retabifying that previously made the side panels jump or reopen oversized.
- **Project Explorer keyboard navigation**: selecting graph items in Project Explorer now activates the selected graph immediately, so after clicking any graph row you can use Up/Down to move through plots quickly.
- **Undo/Redo** are exposed on the Edit menu (Ctrl+Z / Ctrl+Y). They track tab changes, worksheet tabs, and other session actions.
- **Saving** uses `.pypj` project files. When a session contains imported data or generated worksheets PyPlot prompts you to save, discard, or cancel if you try to close the window.
  Shared plugin state: PyPlot now stores a shared plugin project-state envelope for every plugin (selected source paths, plugin-local last directory, auto-load preference, and whether plugin plots were open) and restores it before plugin-specific state, so project reopen behavior is consistent across plugins. If a plugin did not serialize tab details, PyPlot now auto-loads plugin data and regenerates plots when the project indicates open plugin plots.
- **Folder memory** is scoped per plug-in. Import file pickers, graph saves, and TXT exports reopen in the last folder used by that plug-in instead of sharing a single global path; plug-ins can also call `PyPlotPlugin.preferred_export_directory(...)` / `remember_export_directory(...)` to share the same history.
- **Connected folders** are available from the shared import flow. Connected folders are polled for new supported files and newly discovered files are imported automatically; `Refresh connected` lets you force a rescan immediately. Connected folders do not persist across ordinary app restarts anymore; they are restored only when saved as part of a `.pypj` project, and each machine keeps its own local connected-folder override per project path.
- **Microwire Data Builder microscope refresh** now preserves previously collected microscope rows and saved review/override state when a refresh only scans a newly added subset of images, instead of replacing the section with just the newest files. Refreshes also preserve the stored microscope payload itself, so previously reviewed `d`, `D`, and `d/D` values do not disappear when the section rebuilds around manual/image-based microscope work.
- **Plot scope** is shared across plugins. Use the shared plot-scope selector beside the Plot action to choose `Plot new` (append only plots for files imported since the last plot) or `Replot all` (regenerate everything from the current imported selection).
- **Project filenames** default to `<plugin name> YYYY-MM-DD.pypj` (for example, `VSM Temperature Scan 2025-12-03.pypj`). If no plug-in is selected, the suggested name is `pyplot YYYY-MM-DD.pypj`.
- **Legends** default to “text colour follows plot” for every plug-in. Legend options (show symbols, placement, orientation, drag, follow colours) are remembered per plug-in between sessions so each workflow keeps its own defaults.
- **Fullscreen**: maximizing any graph/workbook hides the others and maximizes the active subwindow; switching tabs or double-clicking a different graph keeps fullscreen on (only the active window is visible) until you restore a window to normal. Hidden tabs restored while fullscreen is active now become the sole fullscreen target instead of reappearing as a small normal window. In fullscreen mode the active subwindow now fills the MDI viewport on macOS instead of aspect-fitting to a smaller letterboxed window.
- **Graph window geometry**: shared MDI graph windows preserve the figure aspect ratio during windowed resize/arrangement transitions so displayed proportions stay consistent outside fullscreen mode.
  Fixed-size graph model: figure width/height from Graph formatting now stay fixed as the canonical/export dimensions; resizing graph windows changes only display zoom (DPI scaling), so lines/text/markers scale proportionally instead of being squeezed while real figure dimensions remain unchanged.
  Tab-switch reflow: when activating another graph/workbook tab, PyPlot now re-fits the current figure layout to the active canvas size to avoid oversized empty canvas regions after window/layout changes.
  Cascade sizing: with one visible graph in cascade mode, PyPlot now keeps cascade-style window sizing instead of an oversized first window.
- **Cascade layout persistence**: in cascade mode, activating another graph no longer re-cascades/repositions windows automatically, so manual graph window positions are preserved while you work.
- **Window arrangement**: the shared `Window` menu exposes `Cascade`, `Tile Vertical`, and `Tile Horizontal` for every plugin. Default graph/workbook view is `Cascade`.
- **Legend auto layout**: when legend orientation is `Auto`, PyPlot now prefers vertical layout for dense/long series labels and uses horizontal rows only when labels/space allow it.
- **TXT exports**: the default filename mirrors the current workbook/plot label so exported TXT/CSV files match the names shown in the Project Explorer and carry the sample/procedure context baked into those labels. Shared TXT export now also falls back to visible Matplotlib lines when a plugin does not populate explicit line-state metadata.
- **Shared plot workbooks**: for plug-ins that do not implement their own workbook builder, PyPlot now auto-creates a `Plot data` workbook per graph tab (XY column pairs from plotted lines). This keeps `Export workbooks to Origin...` and worksheet tooling available consistently across plotting plug-ins.
- **Shared Origin fallback**: when a plug-in uses the base `Open in Origin...` action, PyPlot exports the active plug-in’s shared plot workbooks to Origin and creates Origin graphs from those worksheets, so the button works even without a plug-in-specific Origin export implementation. Shared Origin workbook export keeps the Origin session open after transfer.
- **Origin worksheet metadata convention (shared export)**: shared exports apply `Long Name = physical quantity`, `Units = unit`, and `Comments = series/legend label` consistently for all columns. For shared plot workbooks, each X/Y pair now inherits axis metadata from the actual source axis (including multi-axis figures) instead of only descriptor-level labels.
- **Graph export**: `Save graph...` is the single shared toolbar entry for graph export. It opens an options dialog first (format, raster DPI, transparent background) and then the file picker; the last selected format is remembered and reused as the default next time.
- **Check outliers** remains worksheet-based, but it now limits detection to columns that are actually plotted when axis-role metadata is available. Preview graphs show each detected column as a scatter plot against row number so isolated spikes and jumps are easier to inspect before removal.
- **Remove bad data points...** adds a manual cleanup mode for graphs that preserve source-row provenance. Turning it on opens a small always-on-top control window so it is obvious that selection mode is active. Drag a rectangle to add points to the selection, click an already plotted point to toggle it on/off, then remove the highlighted points from the underlying data only after explicit confirmation from that control window. Graph-backed plugin tabs now refresh in place after deletion so the same graph window stays open instead of being torn down and recreated.
- Primary side docks now suppress programmatic visibility/location callbacks during startup normalization and dock retabifying, which keeps Project Explorer/Object Manager widths stable instead of repeatedly reflowing themselves after the session opens.
  Window-state note: when a graph-backed plugin rebuilds a plot after point removal, PyPlot now carries the previous subwindow geometry/maximize state forward so edited graphs stay where they were instead of dropping back to a fresh windowed layout.

## Origin export checklist
- Mirror the Matplotlib view: same title (top X label), axis labels, sample ordering, and delta annotations; hide Origin tick labels and draw manual sample labels when needed.
- Set graph/axis titles with Origin-compatible label commands (`label -n ...` / `label -xb/-yl/-xt/-yr`) so titles render reliably across Origin builds where `PAGE.ANTIALIAS` and some direct axis/title properties are not available.
- In shared exports, prefer the `line` template first, then `ORIGIN`/`scatter` fallbacks, because some Origin 2026 setups emit recurring `LEGEND.SMARTPOS` warnings with the baseline `ORIGIN` template.
- Shared `Open in Origin` now attaches to an existing Origin automation session first and validates the COM bridge before export, so startup failures surface as a clear error dialog instead of delayed crashes.
- Preserve sample labels on X and long name/units/comments rows in the Origin worksheets (baseline, deltas, relative values documented).
- Match line/symbol styles, widths, sizes, and legend entries; ensure text follows line/marker colour in both light/dark graph modes.
- For shared multi-axis exports (for example dual-axis overlays), group XY pairs by axis-title metadata and plot each group on its own linked Origin layer so displacement/load and strain/stress do not collapse onto one Y scale.
- For shared dual-axis overlays with identical segment labels across groups (for example `Loading 1` in both load and stress groups), hide duplicate secondary-layer traces after axis scaling so the exported graph shows one visible curve set by default.
- Use descriptive graph names/long names that match the Matplotlib title and include distinguishing metadata (field strength, temperature, or variant) when multiple graphs share a sample name.
- Build worksheets with units and comments filled (including baselines/deltas/relative columns) and avoid terminal spam (disable tqdm/console progress); keep graph extents so nothing is cropped after export.

## Logger Notes

- `Mini DMA Logger` is a launcher workflow rather than a PyPlot plug-in, but it now follows the same microwire-oriented naming flow as the other loggers: the displayed sample name keeps a human-readable microwire token such as `156/2`, while the base filename uses the file-safe form `156_2`.
- On Windows, Mini DMA can actively auto-detect the connected G&G balance, HMP4030/Owon-style serial supply, and Pololu Tic controller instead of relying on fixed COM assignments. For G&G balances, the normal workflow leaves the scale showing real grams and uses an editable zero-load scale reference, with physical remote tare kept only as an advanced diagnostic.
- Mini DMA's left settings panel guards spin boxes and drop-downs against mouse-wheel value changes, disables horizontal scrolling, and wraps longer notes/log text to the available width.
- Mini DMA hides low-level hardware details such as baud rates, request strings, `ticcmd`, serial numbers, and steps-per-mm behind an advanced hardware panel so routine bench use stays focused on connect, tare, jog, and safety actions.
- Mini DMA reads the Pololu Tic VIN motor-supply voltage during motor status/preflight checks and warns when motor power appears off or too low.
- Mini DMA can optionally use CH1 or CH2 of an HMP4030 to power the motor supply automatically during recipe preflight, while keeping current annealing on the configured annealing channel.
- Mini DMA recipe start now behaves like a preflight: it builds the recipe, auto-detects/connects required scale and supply hardware, reports all missing devices together, and only then starts the session. Long estimates use minutes/hours and a progress bar tracks recipe execution.
- Mini DMA avoids padded zero-only numbers in recipe summaries and clamps below-resolution motion settings to at least one Tic motor step. Manual `Move up` / `Move down` controls are stacked arrow buttons that use true press-and-hold jogging from the last commanded target; held manual motion advances by the configured linear `Manual move speed` in `mm/s`, while short clicks still use the single-click step.
- Mini DMA organizes routine work around `Recipe` and `Sample` tabs, with scale/motor/power-supply setup moved into a lower-priority `Hardware` tab; the Recipe tab shows the current sample name and diameter as a run-identity reminder, the Sample tab remembers the last `.pydpj` project and auto-imports matching diameter data, and the run log is the single visible log surface instead of duplicating lines in the status bar.
- Mini DMA includes separate iso-load, iso-stress, and iso-strain current-sweep recipes for copper-wire bring-up and later microwire work, plus a generic Calibration recipe for stiffness/backlash and stress-strain characterization. Recipe scheduling now uses global control, data-log, and UI-refresh intervals instead of per-recipe frequencies, with the timing controls under `Settings -> Timing...`, while scale polling, Tic status/keepalive, and supply readbacks keep their own hardware cadences. Tic command state is tracked separately from status polling, so calibration micro-moves chain from the last commanded target and log rows use cached/commanded position without forcing a Tic status subprocess; move/halt/zero/keepalive commands go through a persistent in-app dispatcher that coalesces stale target commands and now prefers native PyUSB/libusb Tic control transfers, falling back to `ticcmd` if native USB is unavailable. Current-sweep recipes ramp load/stress/strain targets at configurable g/s, MPa/s, or %/s rates, hold them with dynamic backlash-aware motor corrections while ramping current from a non-zero default so resistance is measurable, and log resistance/current/voltage/mechanics channels during seeking, target ramps, settling, and current updates. Current-sweep and Calibration recipes use the zero-load scale reference, run a mandatory starting-length/preload/return setup with a live setup graph, local pause/stop/progress controls, setup sidecar logs, stable zero-load plateau fallback for `l0` and final zero-load return/recovery, setup time-derived preload `MPa/s`, and setup slack take-up in `%/s`; load/stress target ramps wait for fresh post-move scale feedback before issuing another correction, continue from the last commanded target instead of waiting for slower Tic status polling, use the target-ramp stage speed as the dynamic current-sweep balance ceiling, defer scheduled CSV rows while post-move scale feedback is still pending instead of stopping the run, require current-sweep settle steps to reacquire the requested target before advancing, accept backlash-limited near-target holds instead of looping forever on skipped reversals, size corrections from the scale feedback cadence rather than the faster control timer, detect target overshoot, detect open-circuit wire breaks when voltage is at the limit but measured current collapses near zero, use HMP4030-style 0.2 mA setpoint resolution below 1 A where current is controlled, and max-load safety still allows relaxing moves if the live load is already over the limit. Mini DMA writes each run into a folder containing `measurement.txt`, `measurement.csv`, `metadata.json`, `scale_raw.csv`, `setup.txt`, and `setup.csv`.
- Mini DMA speed-control details are documented in `docs/mini_dma_speed_control.md`, including ramp units, live stiffness scaling, 250 ms scale-feedback prediction, smooth landing speed, servo hold, and backlash-aware reversal handling.
- Mini DMA displays the latest commanded motor speed as equivalent `mm/s`, `g/s`, `MPa/s`, and `%/s` rates, waits for expected motor completion before accepting post-move force feedback, and uses a fully automatic step/noise tolerance floor so load/stress holds do not depend on hand-tuning a value below the physical resolution.
- Mini DMA cleans repeated `_run02` suffix chains from restored base filenames before creating run folders, and the output-folder row includes an `Open` button next to `Browse`.
- Mini DMA has explicit pause/resume and stop handling: pause/stop turn current annealing output off, recipe completion stops the session log, recipe stops/faults keep a resume point and can offer displacement/load recovery without appending recovery samples to the recipe CSV, and starting again can resume from the stopped point or start over.
- Mini DMA keeps the normal four-tile run dashboard for load, displacement, current, and resistance, and opens a temporary dual-axis load/displacement graph only during recovery to zero/start.
- Mini DMA displays and logs applied tensile load as a positive magnitude even when the scale reports negative values while lifting the weight, preserves signed raw scale values for diagnostics, and uses a separate motion-direction setting so tensile displacement can also be positive without coupling it to scale sign. The current G&G scale does not stream passively at `9600`; Mini DMA plans around its measured `ESC+p` response cadence of about 5 Hz and defaults request-mode scale acquisition to 250 ms.
- Mini DMA has an always-visible `EMERGENCY STOP` dashboard button that stops the active session/recipe, halts the Tic motor, and commands the supply output off.
- The Mini DMA measurement roadmap and saved-recipe design notes are tracked in `docs/mini_dma_measurement_plan.md`.

## Automation

- **Machine-facing recipes**: `launcher.py --automation-recipe <job.json>` runs PyPlot in a Codex-oriented batch mode. The recipe can load an existing `.pypj`, activate a plug-in, import files/folders, generate plots, export artifacts, and save a project without going through the interactive launcher.
- **Relative paths**: recipe input and output paths are resolved relative to the recipe file location, which keeps workspace-local jobs portable when they are stored next to sample data or an `artifacts/` folder.
- **Manifest output**: runs can write a machine-readable manifest JSON with the active plugin, loaded/saved project paths, imported paths, workbook/tab counts, current tab details, and exported image paths. When no manifest path is provided, the JSON is printed to stdout.
- **Batch plot exports**: `exports.plot_images_dir` saves every visible plot tab as a deterministic PNG named `<tab_index>-<safe_tab_label>.png`, which is meant for replayable automation and test verification rather than human browsing.
- **Graph/figure automation**: recipe runs can now build worksheet-backed graphs (`build_graphs`) and assemble multi-panel figures (`create_figures`) without using the interactive dialogs, so agent-authored jobs can import tabular data, create exact X/Y plots, and then arrange them into shared-axis layouts in one pass.
- **Current scope**: v1 automation is PyPlot-only. The shared recipe entrypoint reserves `kind: "builder"` for future Microwire Builder / `.pydpj` automation, but that mode is not implemented yet.

## Annotation And Composition

- **Annotate toolbar**: PyPlot now includes a shared `Annotate` toolbar with `Select`, `Text`, `Arrow`, `Line`, `Rect`, and `Ellipse` tools. Text labels are placed on click; arrows/shapes are created by dragging directly on the graph canvas.
- **Object Manager integration**: free text labels and annotation shapes appear in Object Manager alongside axes, lines, and legends, so you can select, recolor, hide/show, or delete them after placement.
- **Text formatting toolbar**: selected text objects now support font family, size, bold, italic, underline, direct colour changes, and mathtext helper actions for subscript, superscript, and combined sub+sup formatting. The richer `Edit…` action opens a text dialog that accepts Matplotlib mathtext syntax such as `$H_{c}$`, `$10^{-10}$`, or `$\\phi$`.
- **Default scientific text look**: shared graph text now defaults to a serif scientific style (`DejaVu Serif` for regular text with STIX mathtext), which keeps Unicode labels working while still producing a paper-like look.
- **Graph composition**: `File -> New -> Compose Graph...` lets you choose existing plotted tabs and overlay their visible series into a new shared PyPlot graph tab. Composed graphs behave like ordinary graph tabs and are saved with the project.
- **X/Y graph builder**: `Create graph...` on the Plot actions toolbar and `File -> New -> Create Graph...` open a worksheet-backed builder where each series row chooses an exact worksheet, X column, Y column, and optional legend label. Built graphs use one shared set of axes, so all added series automatically share the same X/Y scale inside the resulting graph.
- **Figure layout builder**: `Create figure...` on the Plot actions toolbar and `File -> New -> Create Figure...` arrange existing single-panel graph tabs into a new multi-panel figure. The builder now supports configurable rows/columns, drag/move reordering, per-panel title overrides, shared X and/or Y scales, external shared legends, panel labels (`(a)`, `(b)`, ...), panel-label placement/size, exact spacing/margin controls, paper-oriented size presets, tick-direction/minor-tick/scientific-notation controls, manual tick lists, decimal formatting, style presets (`Default`, `Colorblind safe`, `Monochrome print`), and unit-selectable figure sizing with `mm` as the default display unit. Layout figures are saved with the project as shared `layout_graph` tabs.
- **Layout refresh workflow**: layout figures remember their source graph titles, so `Refresh figure` rebuilds the current layout from updated source graphs while keeping the layout configuration and panel-level annotation objects. `Clone figure` duplicates the current layout as a starting point for the next paper revision, and `Figure sources` shows which graphs feed each panel.
- **Templates and house styles**: the figure dialog can save/load a reusable house style as well as full figure templates, so paper layouts can be reapplied across projects without rebuilding the same margins, labels, legend placement, and styling by hand. Saved house styles now auto-apply in the figure dialog and in automation recipes unless explicitly overridden.
- **Batch export**: `Export all figures...` batch-exports the current graph tabs with deterministic numbered filenames for manuscript folders, and recipe automation can export the same batch non-interactively.
- **Annotation workflow**: shared graph annotations now support callout boxes plus copy, paste, duplicate, alignment, numeric positioning, snap-to-position guides, arrow style presets, and z-order control, so figure callouts can be reused and refined across paper panels with less manual rework.

## Importing Data

1. Use the **Import data…** button (or the Data menu) to select files/folders (multi-select folders are supported).
2. Supported formats: CSV/TSV/TXT/DAT/XLS/XLSX/XLSM/JSON/VSM `.vsm-hys-data`, `.vsm-tscn-data`, `.vsm-vir-data`. Plug-ins can add their own loaders (see `PyPlotPlugin.load_data` implementations).
3. After import, plug-ins that set `auto_load_on_import` can register their own workbooks automatically. Plug-ins that declare `requires_imported_data` keep Plot disabled until Load Data (or auto-load) populates their data.
4. All worksheets live under `Imported Data` → `<folder>` → `<workbook>` so every plug-in can reuse them (export to Origin, duplicate, edit columns, etc.).

## Logs

- The **Message Log** dock records plug-in output, path skips, and Origin export diagnostics. Toggle it via the dock switcher on the left edge whenever you need to inspect warnings.
- Project Explorer/Object Manager activation errors (for example, stale item references) are now captured in the Message Log instead of hard-aborting the app.
- Workspace log files under `logs/` now auto-rotate at ~1 MiB with numbered backups (`.1` ... `.5`) so long sessions do not grow `message_log.txt` / `crash_log.txt` without bound.

## Extending / Debugging

- Shared UI helpers live in `plotting/pyplot/window.py` so plug-ins can reuse the same worksheet/graph machinery without reimplementing it.
- Use `docs/todo/pyplot_migration_todo.md` for open work. Update this `pyplot.md` file when you add major features or new plug-ins so other developers can discover them quickly.
- Window layout conventions:
  - Graph/worksheet windows are MDI subwindows (no visible tab bar). Default arrangement is cascading windows; each subwindow keeps the graph aspect ratio during manual resize and arrangement changes, while fullscreen mode fills the available viewport.
  - Graph canvases keep the configured real figure size as the export baseline; MDI arrangement changes now explicitly retrigger display scaling so text, markers, and lines stay proportional after cascade/tile resizing.
  - Ordinary subwindow activation and non-maximize state changes must not recascade manually positioned windows. Only explicit arrangement changes (`cascade`, `tile vertical`, `tile horizontal`) should rewrite MDI graph geometry.
  - Hidden-tab restores during fullscreen mode must route through the same single-window maximize path as ordinary tab switches so only one graph remains visible.
  - When only one subwindow is visible in windowed mode, it expands to fill the available MDI viewport so content is not cropped at the bottom after fullscreen/resize transitions.
  - macOS maximize geometry now compensates subwindow frame/title-bar extents so the active graph canvas fills the viewport without a clipped bottom strip.
  - macOS now keeps maximize/fullscreen state synchronized while switching between graph/workbook subwindows.
  - Maximizing any subwindow maximizes all of them when you switch via the Project Explorer; restoring one returns all to windowed mode.
  - Hidden or newly shown graph tabs must also respect the active fullscreen lock, even if `_global_maximized` is momentarily out of sync during tab/project activation.
  - When adding or updating plug-ins, keep these sizing/fullscreen rules intact and refresh this document if the behavior changes.
- Side-panel stability:
  - Primary explorer/object docks should size through the shared primary-dock handlers only. Avoid extra visibility-triggered normalization hooks or dock-switcher refresh callbacks, because they can create recursive width churn after startup or main-window resize.
  - When persisting side-panel widths, prefer the current measured dock width over an older larger remembered value so narrowed docks reopen at the same width next session.
- Subwindow lifecycle:
  - The close button hides a graph instead of destroying it; reopen via Project Explorer → Plots. Keep windows in fullscreen/windowed mode until the user changes it, and sync that state across subwindows when switching.
  - Visibility queue cleanup now removes deleted subwindow references before activation/limit checks, preventing stale `wrapped C/C++ object ... has been deleted` exceptions.
