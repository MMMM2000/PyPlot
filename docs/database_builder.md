# Database Builder Overview

Microwire Data Builder aggregates per-section measurements (fabrication, annealing, microscope, etc.) into a single combined dataset that can be previewed, filtered, and exported. This document captures expected behaviors so we can test against a consistent spec.

For the dedicated manual fabrication-video workflow, see [Universal Video Builder](./video_builder.md). That tool is separate from the full Microwire Data Builder and keeps fabrication/video review in a single focused window.

## Sections and Data Sources

- Fabrication: metadata columns (length, datetime, mass, resistance, notes), computed e/a ratio, plus any available video-related fields (core/glass temperature, winding speed, glass feeding, underpressure). Imported samples are added here so fabrication lookups work even when no spreadsheet exists yet.
- Current annealing: uses one dedicated `1000 mA` anchor slot plus an aggregated `Other annealing` bucket for every non-anchor run; extra runs surface in "Figure — other annealing" and can be hidden via the visibility dialog. The Builder accepts standard `.txt` logger files plus Košice-style `.dat` files, including cycle-tabular logs with `Ireal_mA`/`Voltage_V`/`Resistance_Ohm` columns and legacy four-column logs where current is stored as amperes despite the header text. The Builder also reports conservative As/Af/Ms/Mf current estimates when heating shows a local resistance drop and cooling shows the corresponding resistance increase along the cooling direction.
- Microscope: d/D values, images, and review state; reviewed values must not be deleted on refresh.
- Current annealing preview semantics: the Builder's dedicated `1000 mA` preview slot is reserved for exact `1000 mA` records. If a microwire only has lower-current annealing files, the UI should show a clear "No exact 1000 mA" placeholder with the available setpoints while keeping the official `File/Figure 1000 mA` export fields empty.
- Transitions workspace: transition review and rollup surfaces are collected under one top-level `Transitions` tab with peer `Annealing`, `VSM`, and `DMA` views. Raw measurement tabs keep source-file import/open/visibility workflows and only expose shortcut actions into the relevant transition view, so transition review is not duplicated as a second primary workflow.
- Current annealing transition review: the `Annealing` transition view summarizes reviewed transition currents and current densities from current-annealing graphs. Section previews and enlarged plots mark detected transition-current candidates directly on the R-vs-I graphs so automatic candidates can be inspected before they are used downstream. Auto candidates are drawn as muted dashed/dotted lines with inline `As1/Af1/Ms1/Mf1` labels, while reviewed/manual values are drawn as stronger `I_As1/I_Af1/...` lines. Reviewed current-annealing values are stored as graph-level `transition_reviews` records, not as sample-level phase-point overrides, so manual values from one graph do not appear in another graph for the same microwire. The review dialog supports fast queue actions (`Accept & next`, `No transition`, `Exclude graph`, `Previous`, `Next unreviewed`), shows each graph's review state in the list, displays live total/done/open/auto/review-state counts, displays automatic and reviewed values separately under the graph, and allows picked current values for `I_As/I_Af/I_Ms/I_Mf` style review labels by selecting a label and clicking or dragging a transition marker to place or move the reviewed vertical line. Individual labels can be cleared without turning the whole graph into `No transition`.
- Transition review performance: graph-click edits update reviewed marker overlays in-place where supported, accept/no-transition/exclude actions avoid redundant outgoing redraws, and Mini DMA review status changes update the active tree row without rebuilding the whole tree unless a filter is active. Set `MICROWIRE_BUILDER_UI_TELEMETRY=1` to enable debug event-loop lag logging, and use `scripts/benchmark_builder_review_smoothness.py --out artifacts/builder_review_smoothness/timings.json` to profile synthetic current-annealing and Mini DMA review actions.
- Annealing transition summary: transition-current markers support two passes (`I_As1/I_Af1/I_Ms1/I_Mf1` and `I_As2/I_Af2/I_Ms2/I_Mf2`). Current annealing transition candidates auto-fill the Annealing transition view when no graph-level review record is accepted. Accepted/manual-adjusted transition-review records override automatic candidates and feed Assemble/export; excluded or no-transition records are retained in the project review payload but do not feed summaries. Current-density values are presented as derived columns in the Annealing transition view and Assemble outputs rather than as a separate workflow.
- Videos: shows the fabrication-style table for video-linked samples, supports manual edits for fabrication fields, and adds `Video end length (m)` + derived `Video microwire length (m)` (baseline minus cumulative Length (m) for the draw). Edits override assembled values. Videos can be opened from the selection.
  Video review state: required empty fields stay red until filled, first-time fills stay green, and overwriting an existing value highlights the cell amber with hover access to the prior value plus a restore action from the review dialog. `Notes` stays neutral instead of being treated as a required review field.
- VSM hysteresis: multiple graphs per sample row (angles grouped per temperature, sub-versions in the same row).
- VSM temperature scan: multiple graphs per sample row (sub-versions in the same row).
- VSM transitions: pick As/Af/Ms/Mf from VSM temperature graphs without switching away from the active graph. The `VSM` transition view can populate directly from saved VSM temperature-scan records or the active VSM temp-scan section. Rows are sample-level rollups, while the preview tabs remain graph-level when multiple VSM scans belong to the same sample; the table shows scan counts and review-state counts so VSM temp-scan record counts and VSM transition row counts are not expected to match. Graph-level `transition_reviews` records store accepted auto values, manual adjustments, no-transition decisions, and excluded scans. The preview uses the same queue language as current annealing (`Accept & next`, `No transition`, `Exclude scan`, `Previous`, `Next unreviewed`), shows automatic estimates separately from reviewed/manual values, and lets the reviewer select As/Af/Ms/Mf and click or drag markers on the active graph to store reviewed temperatures for that scan. Per-label clear controls support partial transitions such as keeping As/Af while removing Ms/Mf; explicit `No transition` remains the separate reviewed-measured-no-transition action. Accepted/manual values feed Assemble/export; no-transition or excluded scans are retained for audit but do not feed final transition-temperature values, and they block Assemble from auto-estimating that reviewed-away sample when all scans are blocked.
- DMA iso-stress: multiple graphs per sample row (sub-versions in the same row).
- Mini DMA: current-sweep and iso-current run folders are grouped by sample and can be opened in PyPlot or exported to Origin from the Builder. Default Mini DMA PyPlot current-sweep graphs use one line+symbol curve per target MPa plateau, a shared global-minimum strain baseline, and a top power axis. Iso-current Mini DMA graphs use strain on X, stress on Y, current/current-density legend labels, a top displacement axis, and a right load axis. Parent-folder discovery skips sidecar folders such as `archive`, `tests`, `automation_history`, scratch/cache folders, and CSV files that do not look like real Mini DMA measurements. The Builder table also reports the strain at the maximum-current point for each stress/load current-sweep curve using a per-curve minimum-length `l0` baseline, including displacement recorded during current-hold recovery, tangent-intersection As/Af/Ms/Mf current estimates when a heating/cooling current cycle is available, plus the inferred break stress/current when a voltage-limit current collapse is detected. The Mini DMA table shows cached graph thumbnails for visible rows, including iso-current stress-strain previews. The `DMA` transition view opens the per-stress review dialog with sample/run/stress navigation, accepted/rejected filters, strain and resistance context, transition markers, fit-line toggles, separate automatic and reviewed I_As/I_Af/I_Ms/I_Mf values, click-to-place and draggable reviewed transition-current markers, and per-label clear controls on the graph; run data is loaded lazily so the dialog appears before heavy transition extraction starts. Review decisions are stored per run/stress/load target with accepted/manual, no-transition, and excluded states, and the dialog reports total/done/open/auto/accepted/manual/no-transition/excluded counts using the same queue vocabulary and status colors as current annealing and VSM. Reviewed values replace automatic Mini DMA transition-current summaries in Assemble/export outputs, and cleared automatic labels are omitted from the reviewed summary without implying `No transition` for the whole target. Iso-current runs are still shown as graphs but are not treated as transition-current candidates. Mini DMA imports are gated per exact sample/variant: when the newest active run is not clearly finished in `metadata.json`, the Builder and Word-report source discovery skip all Mini DMA runs for that sample instead of falling back to older runs.
- Manual stress/strain: multiple dual-axis overlay graphs per sample row from manual stress/strain logger TXT files. The section includes an optional side preview panel; double-clicking a preview picks displacement/load/strain/stress values into dedicated columns that can be carried into Assemble, and the picker can target either the standard/manual stress/strain columns or the fracture load/strain/stress columns.
- Section search: all builder tables now expose a search box that filters rows across visible columns, including the graph/data sections and the custom transition and Compare views. Measurement sections that carry source paths also show a `Source` filter derived from known roots/patterns such as Praha and Košice.
- Microscope other ends: filenames with an `oe` suffix (for example `Ni46Fe23Ga23Co8 1-1oe core`) are treated as separate samples, and the Microscope tab can show or hide those `oe` rows without deleting them.
- FMR: Field vs X/Y voltage plots from CSV files; multiple graphs per sample row.
- Strain: stress/strain entries tied to composition + microwire; d auto-filled from microscope when available.
- Assemble: combined preview and export configuration.
- Analysis: `Analysis -> Analyze assemble data...` opens the separate Microwire EDA tool using the current filtered Assemble rows. The report generator is read-only, analyses only data already present in Assemble, shows a progress dialog while it runs, and writes into a dedicated report subfolder. When launched from a `.pydpj` path directly, the autonomous CLI flow now uses a disposable copied project file by default so the source project is not mutated during analysis.
- Assemble imports: spreadsheet rows can be imported and merged with the assembled dataset; imported rows are tagged via the "Data source" column and enriched with fabrication metadata where possible.
- Data menu: import external workbooks, toggle visibility of imported-only rows, or remove imported data entirely. Optionally separate imported Fabrication rows under an "Imported data:" divider. Imported workbooks appear under Project Explorer.
- Imported workbook source workflow: imported workbook rows participate in the same `Source` filtering model as Praha and KoÅ¡ice data, using the `Imported` source label instead of a separate provenance mechanism.
- Settings menu: hide optional legacy/derived views such as Annealing transitions, Strain, and Manual stress/strain without unloading their data from saved projects, Assemble, or exports.
- Compare: subset of rows for side-by-side comparison.

## Sample Naming and Grouping

- Sample identification is always the leading composition + draw-piece pair in the folder/file name, e.g. `Ni50Fe27Ga23 5-4` -> Composition `Ni50Fe27Ga23`, Microwire `5/4`.
- Suffixes appended directly to the draw/piece (for example `10-5oe`) become part of the microwire key and create a separate sample row.
- Extra suffixes after the microwire token (e.g. `no glass`, `NG CA`, `s1`, `s3`) define sub-versions for the same sample; they should appear as additional graphs in the same row.
- One row per sample in the VSM/DMA sections; multiple graphs for the same sample are placed side-by-side in that row.
- Hidden graphs (visibility dialogs) are excluded from Assemble/Compare/exports and from HTML compare output.
- Visibility dialogs support per-graph group toggles (for example, hide/show an entire temperature group in VSM).
- Graph titles should include the suffix label (for example, `Ni50Fe27Ga23 10/5 (NG CA)` or `Ni50Fe27Ga23 11/1 (s3)`).
- Source provenance is an internal Builder concern, not part of public sample identity. Multi-site imports should keep `source_id`/source label/source path/hash/modified-time metadata available for Builder filtering, grouping, audit manifests, and accidental-mixing checks, while public Assemble exports omit Praha/Košice provenance columns by default so boss-facing workbooks present one unified database.

## Current Density Requirements

- Support two measurement passes: As1/Af1/Ms1/Mf1 and As2/Af2/Ms2/Mf2.
- Derived columns include the deltas between passes (As2-As1, Af2-Af1, Ms2-Ms1, Mf2-Mf1) and Mf1-Af1 / Mf2-Af2.
- Provide the current density columns (A/mm^2) for each transition when diameter is known.
- Respect the active selection (e.g. editing Af1 should not overwrite As1).
- Store reviewed transition-current edits in the annealing `transition_reviews` project payload with one record per measurement graph. Legacy `phase_points` data is not authoritative for new reviews and should not be applied blindly across multiple graphs from the same microwire.
- Use `scripts/audit_current_annealing_transition_reviews.py --project <copy.pydpj> --out artifacts/current_annealing_transition_review_audit` or `--input-json <review_dump.json>` to compare reviewed/manual values against current automatic candidates. The audit output highlights missing automatic labels, manual deltas, and paired loop asymmetries such as `Ms2` missing when `Ms1` is present.
- Assemble preview/export should include the As*/Af*/Ms*/Mf* columns even when they originate from current-density or transition-review inputs. When a reviewer marks a transition measurement as no-transition or excluded, Assemble keeps the numeric transition columns blank and exposes the reviewed state through the visible transition status/review-count columns instead of making the row look unmeasured.
- Current-density summary/export should include a density value for every reviewed transition current when diameter is known (`J_As1`, `J_Af1`, `J_Ms1`, `J_Mf1`, and second-pass equivalents).

## Microscope + Strain Workflow

- Manual microscope entries are preserved; once a value is reviewed it must remain on refresh, and review color should track the value.
- Keyboard flow: Tab moves between d and D cells within the table; Enter should advance to the next editable field without jumping to the start.
- Strain entries:
  - d should default from microscope when available.
  - Weight and stress are linked; editing one should recalculate the other.
  - Export stress, weight, and mode (single vs dual span) to the database.
  - Enter submits the entry; Tab cycles between input fields.

## Assemble (Preview + Export)

- Export is driven by one button: open settings, adjust, then export.
- "Preview database" shows the combined view using current column selection and sorting; "Combine database" is the full merge for export outputs.
- `Analyze...` opens the standalone Microwire EDA workflow. When a preview is available it uses the current filtered Assemble rows as its default scope, keeps the current selected subset available as an alternate scope, and writes a read-only HTML/Excel/CSV/manifest report bundle without modifying the `.pydpj` project.
- Column selector must include every column from every section, including graph columns; graph columns are off by default.
- Column order, visibility, and multi-column sort are persisted in the `.pydpj` project.
- Assemble preview includes a quick search box that filters rows across currently visible columns and a `Source` filter for internal Praha/Košice review; saved projects keep the active search/filter state.
- Microwire sorting is numeric (10/5 comes after 5/4).
- Graph preview panel is optional. When enabled, selecting a row shows current annealing, VSM, DMA, manual stress/strain, and FMR previews for that row.
- "Add to compare" uses the current row selection and populates the Compare tab.
- Multi-graph previews in non-Compare sections are laid out horizontally; Compare stacks graphs vertically with rows tall enough to show full-size plots.
- The bottom-right `Export worksheet...` shortcut was removed; use the top-left `Export...` flow for Assemble exports.

## Compare

- Holds the selected rows from Assemble.
- Default view is a samples-as-columns matrix: columns are `Composition Microwire`, rows are selected fields, and graph rows render inline previews for side-by-side comparison. Selecting any cell highlights the full field row.
- Users can switch back to the row-based view and choose which fields to show + their order.

## Export Targets

- CSV, Excel, HTML (self-contained) outputs are supported.
- Public Assemble workbook exports can be generated without opening the Builder UI:
  `launcher.py --microwire-assemble-export <project.pydpj> --microwire-assemble-output <assemble_public.xlsx>`.
  The default `public` preset writes a clean `Assemble` sheet for supervisor/boss sharing, flattens list/object cells like the interactive Assemble export, and removes visible source/provenance/internal columns from the main sheet. Dropped traceability columns are preserved in a hidden `Assemble audit` sheet and in the sidecar manifest. Add `--microwire-assemble-rebuild` to rebuild Assemble transiently from section payloads in a disposable copied project before export.
- Word sample reports can be exported from Assemble as one `.docx` per sample row. The reports begin with a compact Microwire data table in the same data-column order used by the Assemble view, including empty values, then microscope dimensions/images. Measurement graph sections for current annealing, R vs T, VSM temperature scans, VSM hysteresis loops, DMA iso-stress, Mini DMA, manual stress/strain, and FMR are now data-driven: a section is written only when that exact sample has an accepted Origin object or graph/reference content for the section. Empty measurement sections are skipped instead of producing placeholder headings.
- Word sample reports embed generated Origin graph pages as editable Word OLE objects when Origin and Microsoft Word automation are available. Assemble and project-based CLI reports reuse the existing PyPlot Origin export paths for graph families that have measurement sources in the Builder project, including R vs T, so exported graph titles, legends, line/symbol styling, and color semantics match the PyPlot graphs. Saved Origin graph pages or live PyPlot-created Origin pages are copied through Origin and pasted into Word as editable OLE objects so they fit inside the page. VSM temperature scan report exports use the normal PyPlot/Origin TScan graph with separate heating/cooling and combined low/high field axes, while derivative/smoothed/overlay workbooks are left to interactive PyPlot exports. Graph descriptors that visibly belong to another composition/microwire are rejected from that report section and recorded in the export manifest instead of being inserted into the DOCX.
- Word sample reports can also be generated without opening the Builder UI: `launcher.py --microwire-word-report <project.pydpj|assembled.xlsx|RvsT.csv> [--microwire-word-sample "Ni50Fe27Ga23 12/2"] [--out <dir>]`. Project inputs merge the saved Builder section rows directly so reports can include samples that are present in measurement sections even when the saved Assemble table is stale, and they discover matching R-vs-T CSVs and Mini DMA run folders from the project folder or from the real measurement-data root referenced by section source paths. Direct R vs T CSV inputs create a sparse sample report with an embedded R-vs-T Origin OLE graph object when Origin and Word automation are available. Batch CLI exports can pass `--microwire-word-graphs-only` to keep only samples with accepted section content. The CLI writes `docx_export_manifest.json` plus `docx_export_manifest.csv`; the JSON manifest records included, skipped, invalid, and missing-artifact measurement sections, accepted Origin graph artifacts, and attempted/succeeded/failed/skipped/missing Word OLE insertions so later runs can identify which DOCX files are tied to changed, rejected, or unembedded source graph files.
- Long Word exports can be wrapped in a machine-readable job request with `launcher.py --microwire-word-job <job.json>`. The job wrapper preserves the existing Origin OLE export behavior while adding status, progress, manifest, log, and cancel-marker paths for subprocess use. See `docs/mw_builder_process_jobs.md` and `docs/automation_templates/microwire_word_job.json`.

## Agent Automation

- Builder automation recipes can update a copied `.pydpj` project without opening the Builder UI. Use `kind: "builder"` / `action: "update_section"` with a supported section such as `microscope`, `annealing`, `vsm_temperature_scan`, `vsm_hysteresis`, `dma_iso_stress`, `mini_dma`, `shape_memory_stress_strain`, or `fmr`. The recipe scans the provided files or folders, merges parsed records or microscope image references with existing section records, saves the updated copied project, and writes a JSON manifest. Add a following `action: "rebuild_assemble"` command to refresh the saved Assemble rows from the updated section payloads in the same copied project.
- Builder automation recipes can add `action: "export_assemble"` after saved rows exist or after `rebuild_assemble`. This writes the same public workbook/manifest as the direct CLI path, with the public sheet hiding source/provenance/internal columns by default and an audit sheet retaining those values for reproducibility.
- Section update commands can set `exclude_dir_names`, for example `["archive", "automated_control_tests"]`, to avoid recursively importing old or diagnostic runs from a measurement folder.
- Fabrication should be part of the master `.pydpj` refresh checklist when new fabrication spreadsheets exist, because new measured samples often need updated fabrication metadata before Assemble and DOCX exports are final. The current `update_section` automation command does not yet support `fabrication`; use the Builder UI or a dedicated fabrication refresh helper for now, and record clearly when no matching new fabrication files are available. Use [Praha Microwire Database Update Checklist](./automation_templates/praha_microwire_database_update_checklist.md) next to the JSON recipe so this decision is reproducible instead of ad hoc.
- Builder automation recipes can also maintain a timestamped database folder by setting `database_dir`. The root keeps `microwire_database_latest.pydpj` and `update_manifest_latest.json`; each successful run writes the new project and manifest through same-directory temporary files, promotes the newly generated project to the latest path, and only then archives the previous latest files under `archive/` with the run timestamp. If `project` is omitted, the recipe uses the current latest project from that database folder. In the Builder Settings menu, enable `Open latest database project on startup` and set the database folder to make manual launches open that folder's current `*_latest.pydpj` instead of the older last-opened project. Recent database working/archive copies still resolve back to the database root's `*_latest.pydpj`.
- Builder project saves now embed graph-section payloads alongside the section rows so copied projects can restore VSM temperature scan records without relying on global AppData cache files.
- HTML export must not require the Videos section to be processed, and includes a compare view (Ctrl/Cmd-click rows to compare).
- Matplotlib/Origin outputs should use the same rows and columns as the Assemble preview.
- No PyPlot UI should be embedded inside the builder; graphs are rendered as static previews like the current annealing section.
- Microwire EDA outputs are separate from Assemble exports: the EDA tool writes its own HTML report, summary workbook, canonical CSV, manifest JSON, and optional figure bundles to a dedicated subfolder under the chosen report directory.

## Microwire EDA

- Microwire EDA is a separate read-only workflow that can load either a Builder `.pydpj` project or an assembled spreadsheet export.
- The current analysis is endpoint-first rather than broke/OK-first. Modern measured endpoints (`Strain (%)`, `Fracture strain (%)`, `Stress (MPa)`, `Fracture stress (MPa)`) are the primary outputs; legacy broke/brittle labels are retained only as optional auxiliary context.
- For `.pydpj` inputs, Microwire EDA now prefers a copy-safe autonomous flow and can rebuild Assemble rows transiently from the Builder project sections when the saved Assemble payload is missing or when a force-rebuild run is requested.
- The generated bundle now includes the HTML report, summary workbook, canonical CSV dataset, findings JSON, findings Markdown brief, and manifest JSON. Findings focus on what the data currently supports and which follow-up experiments are worth running next.
- Standalone command entrypoint: `launcher.py --microwire-eda <project.pydpj|assembled.xlsx> [--rows all|filtered|selected] [--out <dir>] [--microwire-eda-title <title>] [--microwire-eda-working-copy-dir <dir>]`.
- Builder-launched analysis uses the current Assemble preview rows directly when available so the report matches the visible filtered subset rather than silently reverting to the full project.
- See `docs/microwire_eda.md` for the full autonomous workflow, copy-safe rules, and RF_EDA reference alignment.

## Logging and Diagnostics

- Message Log captures warnings/errors for builder actions.
- Developer menu includes "Capture Message Log to File" to write to `logs/message_log.txt`.
- Unread errors should highlight the Message Log dock/button.
